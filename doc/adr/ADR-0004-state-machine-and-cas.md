# ADR-0004: 聚合根状态机内聚与数据库 CAS 并发防护

## 状态

已接受 (Accepted) — 2026-09

## 上下文 (Context)

订单具备明确的生命周期（待支付 UNPAID -> 已支付 PAID / 已取消 CANCELLED）。
在实际线上环境中，存在用户双击支付、网络重试并发触发、已取消订单被延迟回调篡改状态等并发不一致风险。
传统做法要么在 Service 层堆砌大量 `if-else`，要么依赖重型分布式锁，容易出现遗漏或性能瓶颈。

## 决策 (Decision)

1. **聚合根自治状态机**：
   - 聚合状态字段私有化，禁止暴露外部 setter；
   - 状态迁移只由聚合根方法（`pay()` / `cancel()`）驱动，在内存中强校验前置合法性；
2. **底层 SQL CAS 原子兜底**：
   - 仓储层更新状态时不使用无条件覆盖，而是携带前置期望状态：
     `UPDATE t_order SET status=?, gmt_modified=? WHERE id=? AND status=?`；
   - 若受影响行数小于等于 0，说明并发冲突或状态已被其他线程抢先迁移，立即抛出 `ORDER_CONCURRENT_MODIFY` 并回滚事务。

## 后果 (Consequences)

### 正向收益

- 无需依赖 Redis 分布式锁即可保证单单状态流转的原子性与绝对一致性；
- 状态机规则完全内聚在领域聚合根内，规则变更只需修改聚合根代码。
